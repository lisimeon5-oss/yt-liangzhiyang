# 多商户砍价（develop-lang）

采用 Java 单商户的金额砍价玩法。用户发起后自动完成首刀，好友逐次砍价，最后一刀精确到达底价；人数包含发起人。每个活动关联一个本店普通实物商品 SKU，每次购买一件。

## 部署

1. 备份数据库，执行 `sql/20260924_merchant_bargain.sql`。脚本只新增三张表与后台菜单/权限，不修改既有商品和订单数据；可重复执行。
   然后执行 `sql/20260924_bargain_menu_order.sql`，将平台、商户的砍价菜单放在拼团紧下方。已安装砍价功能的环境只需执行这份排序脚本，清理应用 Redis 中的 `platformMenuList`、`merchantMenuList` 两个菜单缓存，再退出后台重新登录刷新菜单（不要清空其它缓存）。
2. 构建并更新 Java `crmeb-admin` 和 `crmeb-front`（包含本次 common、service 依赖）。
3. 构建并更新 `mer_mer_admin`、`mer_plat_admin`、`mer_uniapp`。必须同时更新，旧前端没有活动入口。
4. 后台角色管理分配新增菜单与权限：商户 `merchant:bargain:list/save`，平台 `platform:bargain:list/audit`。不自动扩大已有员工权限，更新后重新登录刷新权限。
5. 商户后台「营销 → 砍价活动」创建；平台同名页面审核；审核通过后可展示。
6. 平台或商户首页装修，在「营销组件」中添加「好友砍价」，可设置横向/纵向布局、展示数量（1–30，默认 6）、多语言标题/图标、颜色及间距，保存发布装修。用户端自动展示已审核、上架且在活动时间内的活动；平台汇总所有商户，店铺和商户自定义页面仅查询本店。点击商品进入砍价详情，「更多」进入支持分页的活动列表，组件的展示数量不限制列表总数。装修预览使用示例商品，前端以实际有效活动为准，无数据隐藏模块。
7. 也可在装修链接选择器中选择「砍价活动」，关联到轮播、导航或图片入口。平台列表 `/pages/activity/bargain/index`；店铺列表附带 `?merId=商户ID`。新增装修组件需更新两个管理后台和 `mer_uniapp`，无需额外 SQL。

## 规则与数据

- 起始价不能超过选中 SKU 售价；底价至少 0.01，每次有效砍价至少 0.01。
- 所有参与记录使用活动统一结束时间。发起砍价不锁库存；下单时同时占用活动名额和原商品库存。
- 同一好友只能为同一记录砍一次，另外限制每个活动帮助他人的次数；自动首刀不占用帮助好友次数。
- 已参与的活动不允许修改商品、价格和人数规则；可下架。改规则应创建新活动。
- 只有发起人达到底价后才能下单；服务端重新核对记录、用户、商户、商品、SKU、价格和数量。
- 不叠加优惠券、积分抵扣、会员折扣，不参与商品分佣；配送及商户结算沿用现有交易流程。
- 未支付订单取消或超时取消：返还库存和活动名额，未过期时可用原成功记录重新下单。
- 已支付订单售后沿用现有退款流程，不重新赠送砍价资格，不返还已消耗的活动购买名额。
- 主订单营销类型为 3；订单明细保留原商品/SKU标识，以兼容发货、评价及普通商品库存回滚。

## 多语言

活动名称、说明分别使用 `name_json`、`description_json`，以语言编码为键；商户编辑页从现有平台启用语言接口动态生成输入项。新增语言不用增加数据库列，停用语言不删除历史翻译。没有译文时回退到活动默认内容。

界面与错误提示接入现有语言包，附带中文、英文、泰文、缅文。以后增加新的界面语言时，需要像其它模块一样补充对应 `bargain` 翻译键；活动内容结构无需改动。

## 上线前联调清单

- 两个商户各创建活动，验证无法查看/修改其它商户活动；平台审核与下架立即生效。
- 发起人自动首刀，两位好友依次帮砍；重复点击或两个浏览器同时帮砍，不重复计数，最终精确到底价。
- 非发起人、未成功记录、更换 SKU、多件购买、过期及下架活动不能下单。
- 同一成功记录并发下单只生成一个有效订单；取消后库存只返还一次。
- 完成一笔测试支付，核对商户订单、配送、退款与结算；分享页的订单入口跳转支付拆分后的商户订单。
- 切换全部启用语言，检查列表、详情、按钮、报错和长文字；新增/停用一种语言验证活动编辑输入项随配置变化。

代码级回归覆盖金额边界、商户隔离、购买者/SKU/数量校验、活动有效期及重复助力等；生产环境完整支付与真实数据库并发仍需部署到测试环境完成上述联调。


### Telegram 砍价分享入口

在 `mer_uniapp/config/telegram.js` 设置公开小程序入口 `TELEGRAM_MINI_APP_URL`（`https://t.me/<bot>/<app>`，或已启用 Main Mini App 的 `https://t.me/<bot>`）。禁止填入 Bot Token。未配置时不会退回复制 localhost 网页链接。

分享使用 `startapp=bargain_<recordId>`，Telegram 内由用户在好友选择界面确认发送。接收方启动后读取 `start_param` / `tgWebAppStartParam`，等待现有自动登录成功，再进入该砍价记录。只携带记录编号，不传递发起人的账号、token 或 URL 中的登录 id。PC Telegram 内不跳转到普通 PC 预览壳。

发布后需双账号验证：A 发起砍价并分享，B 在 Telegram 打开链接，确认以 B 身份进入对应记录、显示帮好友砍价；B 助力后 A 刷新查看进度。另验证退出后冷启动、中文与其他语言、失效记录。当前自动登录沿用现有实现；入口参数本身不提供身份认证。
